# Инструменты чата (hh.ru/chat) — implementation plan

## Цель

Два ручных инструмента прямо на странице `hh.ru/chat`, встроенных в интерфейс hh.ru:

1. **Быстрая отправка** заранее заданных сообщений в открытый чат одним кликом.
2. **LLM-ответ** на конкретное сообщение работодателя — черновик вставляется в поле сообщения, отправка — только руками пользователя.

Расширяет `hh-auto-otclicker` (см. [01-hh-auto-otclicker.implementation-plan.md](01-hh-auto-otclicker.implementation-plan.md)) — та же архитектура: программная инъекция content script через `webNavigation`+`scripting`, настройки и диагностический лог в `chrome.storage.local`, единая консольная конвенция логов (эмодзи-префикс на модуль).

## Предыстория: отменённая версия

Первая версия была автоматической — кнопка «Заспамить чаты» обходила весь список чатов сама (скролл виртуализированного списка, чёрный список уже обработанных id, отправка одних и тех же сообщений везде подряд). Заказчик отклонил: слишком грубо для чатов, где уже идёт реальная переписка — например, у рекрутера в чате может висеть открытый вопрос, и автоматическое «Здравствуйте, давайте пообщаемся» в ответ неуместно.

Заменили точечными ручными кнопками: расширение ничего не обходит и не решает само — только даёт быстрые действия внутри чата, который пользователь уже открыл сам.

## Разведка целевой страницы (debug-htmls)

По снапшотам `hh.ru/chat/<id>` разобрана структура, нужная для обеих кнопок:

- **Список чатов слева виртуализирован** (react-window-подобно: строки абсолютно спозиционированы, DOM переиспользуется при скролле, количество узлов в DOM примерно постоянно). Карточка чата — `<a data-qa="chatik-open-chat-<id>" href="https://hh.ru/chat/<id>?...">`; тот же `<id>` появляется в URL открытого чата.
- **Строка превью последнего сообщения** в карточке чата — `nextElementSibling` сразу после `[data-qa="chat-cell-subtitle"]`. В той же строке hh.ru рисует синий бейджик непрочитанных `[data-qa="chatik-info-badges"]`, когда он есть; у открытого/прочитанного чата место обычно пустует.
- **Поле ввода и кнопка отправки** — `[data-qa="chatik-new-message-text"]` (textarea) и `[data-qa="chatik-do-send-message"]` (кнопка, задизейблена при пустом поле). Присутствуют в DOM только тогда, когда в чат можно писать — hh.ru сам решает это по множеству причин (архив вакансии, нет приглашения работодателя, блок по резюме и т.д.) с разным текстом предупреждения под каждую. Вместо распознавания каждого варианта текста — везде в этом плане просто проверяется наличие composer'а.
- **Сообщение в переписке** — контейнер `[data-qa="chatik-chat-message-<id>"]` (не путать с `[data-qa="chatik-chat-message-<id>-text"]` — это его дочерний узел с текстом). Входящие (от работодателя) отличаются от исходящих (от соискателя) CSS-классом на бабле: `chat-bubble_incoming` против `chat-bubble_outgoing`. Оба — CSS-modules классы с build-специфичным хэш-суффиксом (`chat-bubble_incoming--CgAKL4FOU0shOYzo`), матчатся через `[class*="chat-bubble_incoming"]`, а не точным именем.

## Ключевые архитектурные решения

- **Ничего не обходится и не запоминается само.** Ни автосписка чатов, ни чёрного списка — пользователь сам решает, в какой чат и когда нажать кнопку.
- **Один общий poll (500 мс) на обе кнопки**, а не MutationObserver и не разовая проверка при заходе на чат. Причины, актуальные для обеих фич разом: (1) hh.ru — SPA, чат открывается/закрывается без перезагрузки страницы; (2) список чатов виртуализирован — карточка активного чата то есть, то нет в DOM при скролле списка; (3) composer может появляться/исчезать с задержкой после переключения чата или изменения статуса переписки. Простой поллинг закрывает все три случая одним и тем же кодом, без отдельной обработки на каждый триггер.
- **Наличие кнопки = наличие composer'а**, и только это. Не пытаемся распознавать текст каждого предупреждения hh.ru о причине блокировки — не нужно поддерживать список формулировок, которые к тому же меняются.
- **Якоря — по `data-qa`/относительному положению в DOM, не по хэшированным CSS-классам**, кроме единственного места, где `data-qa` нет вообще (`chat-bubble_incoming`/`_outgoing` — тогда матчим по стабильной части имени класса через `[class*=...]`).
- **Клик — с повторной проверкой состояния**, не доверяя последнему снимку из poll'а: id текущего чата и наличие composer'а перечитываются заново в момент клика — защита от гонки «переключили чат/страница перерендерилась за долю секунды до нажатия».
- **Рефакторинг `lib/llm.js`: перебор моделей по fallback вынесен в общий `tryModelsInOrder`.** До LLM-кнопки такой цикл («пробуем модели по очереди, логируем, останавливаемся на первой пригодной») жил только внутри анкетного `generateAnswers`; новая функция с тем же циклом стала бы копипастой. `tryModelsInOrder` владеет только циклом и формой результата (`{success, data, metadata}` / `{success:false, error}`), а что считать «пригодным ответом» — решает переданный вызывающей стороной `parseResponse`:
  - у анкеты — строгий JSON `{answers: [...]}` + валидация количества ответов (маппится потом на конкретные radio/checkbox);
  - у чата — любой непустой текст (вставляется в textarea как есть, строгий контракт не нужен).

  Внешний контракт `generateAnswers` не изменился (те же поля на входе/выходе) — `vacancy-questionnaire.js` правок не потребовал. `callOpenRouter` получил необязательный параметр `systemPrompt`, чтобы не дублировать сам HTTP-вызов к OpenRouter.
- **Свой промпт для чата, отдельно от анкетного «Стиля ответов».** Разный контекст использования — пользователь пишет их независимо.
- **LLM-ответ вставляется, никогда не отправляется автоматически.** Если в поле уже что-то есть (черновик или предыдущий вариант ответа) — новый текст добавляется через `\n\n`, не затирая написанное; можно перегенерировать с другим промптом и сравнить варианты, не потеряв предыдущий.

## Компоненты

- **`content-scripts/chat-tools.js`** — единственный content script для `/chat*`, общий для обеих кнопок:
  - poll каждые 500 мс: определяет id текущего открытого чата и наличие composer'а;
  - **кнопка быстрой отправки** — вставляется/убирается у карточки открытого чата в списке слева; по клику отправляет строки из настройки по очереди с паузой 1 сек, дожидаясь подтверждения (поле реально очистилось) перед следующей;
  - **кнопки LLM-ответа** — по одной на каждое входящее сообщение с непустым текстом; по клику показывает спиннер, запрашивает ответ у `background.js`, вставляет результат в composer.
- **`lib/llm.js`** — `generateAnswers` (анкета, без изменений в контракте) и новая `generateChatReply` (свободный текст) на общем `tryModelsInOrder`.
- **`background.js`** — инъекция `chat-tools.js` на `/chat*` (та же схема `webNavigation`+`scripting`, что и у остальных content scripts); обработчик сообщения `HHAA_GENERATE_CHAT_REPLY` (зеркалит существующий `HHAA_GENERATE_ANSWERS`).

## Хранилище (chrome.storage.local, `hhaa_settings`)

- `chatQuickMessagesRaw` — сообщения для быстрой отправки, textarea, одна строка = одно сообщение. Пустые строки игнорируются (не отправляются) — ими удобно визуально отделять сообщения друг от друга в самом поле настроек.
- `chatLlmPromptRaw` — промпт для LLM-ответа в чате; вместе с уже существующими `apiKey`, `legend`, `llmModelsRaw` полностью описывает запрос к LLM.

## Визуальный стиль

Единый со стилем панели ([01-hh-auto-otclicker.implementation-plan.md](01-hh-auto-otclicker.implementation-plan.md) → «Визуальный стиль»): брендовый красный градиент (`#d6001c` → `#a80016`), инжектится в `<head>` страницы hh.ru отдельным `<style>` (страница hh.ru не подключает CSS расширения).

- **Кнопка быстрой отправки** — прямоугольная, крупная (110×33px, скругление 10px) — специально увеличена, чтобы не пришлось целиться. Без эмодзи — символ `ᯓ➤` по центру.
- **Кнопка LLM-ответа** — компактная пилюля с эмодзи 🤖, строчкой внутри блока сообщения. Во время запроса — CSS-спиннер вместо содержимого кнопки (без сторонних библиотек), кнопка задизейблена; после ответа (успех или ошибка) возвращается кликабельной для повторной генерации.

## Чеклист внедрения

- ✅ `lib/storage.js`: `chatQuickMessagesRaw`, `chatLlmPromptRaw` в настройках
- ✅ `lib/llm.js`: `tryModelsInOrder` (рефакторинг), `generateChatReply`, `callOpenRouter` принимает `systemPrompt`
- ✅ `background.js`: инъекция `content-scripts/chat-tools.js` на `/chat*`, обработчик `HHAA_GENERATE_CHAT_REPLY`
- ✅ `content-scripts/chat-tools.js`: poll, кнопка быстрой отправки у карточки чата, кнопки LLM-ответа на входящих сообщениях, спиннер
- ✅ Настройки: textarea сообщений для быстрой отправки + textarea промпта для LLM-ответа в чате
- ⭕ Ручная проверка в браузере:
  - быстрая отправка: чат с обычной перепиской, чат без composer'а (кнопка не появляется), переключение между чатами, скролл списка с открытым чатом вне видимости
  - LLM-ответ: сообщение с несколькими вопросами, повторная генерация с изменённым промптом (ответ добавляется, не затирает), чат без composer'а (кнопки нет), отсутствие API-ключа (понятная ошибка в diagnostic-логе)
