# 06 — Отбор вакансий по Jev перед откликом

## Цель
- Перед откликом спросить модель Jev (план 04), подходит ли вакансия; неподходящие пропускать.
- Галочка в настройках. Выключен — поведение и расходы как без фичи.
- Промпт и порог задаются один раз в настройках; на ходу ничего не настраивается.
- Любой обрыв (Стоп, закрытая вкладка, ошибка, перезапуск браузера) — продолжение с того же места без повторных платных запросов.
- Один единый чёрный список вакансий, один путь решения на карточку.

## Как работает
Карточка за карточкой, как сейчас. К правилам добавляется один шаг: вопрос модели про эту единственную вакансию.

1. Уже обработана на странице → пропуск.
2. Нет кнопки отклика → пропуск.
3. Вакансия в чёрном списке по причине не про отбор (анкета, попап, ручной пропуск) → пропуск.
4. Компания из чёрного списка компаний, стоп-слово в названии → пропуск (как сейчас, с записью в журнал откликов).
5. Отбор выключен → отклик как обычно.
6. Отбор включён:
   - В чёрном списке есть отказ отбора по текущему вопросу → решает сохранённая вероятность против текущего порога, запроса нет.
   - Записи нет → один запрос (~0,5 с). Вероятность ниже порога → запись в чёрный список с причиной «отказ отбора», пропуск. Не ниже → отклик как обычно, записи нет.

Отказы запоминаются, одобрения нет: одобренной вакансии кнопка отклика исчезает после отклика. Потерянное при обрыве — один запрос стоимостью доли копейки.

## Решения

**1. Один чёрный список, причина — поле записи.** Записи: вакансия, название, компания, время, причина. Для отказа отбора добавляются вероятность и отпечаток вопроса.
- Анкетные причины (вопросы в попапе, обязательное письмо, LLM не справился, ручной пропуск и т.п.) действуют всегда и навсегда, как сейчас.
- Отказ отбора — вердикт «на сегодняшних настройках»: действует только при включённом режиме, только при том же вопросе и только пока вероятность ниже текущего порога.
- Отсюда без единой кнопки и пересчёта: порог двигается в обе стороны без запросов; смена промпта, шаблона вопроса или модели делает старые отказы недействующими; выключение режима сразу открывает отклонённые для отклика.
- Имя хранилища отражает суть: «чёрный список вакансий», не «анкетный». Старый ключ переносится одноразово в той же поддержке хранилища, что уже запускается при установке, обновлении, старте и импорте (импорт старого файла получит перенос сам).
- Существующая кнопка «Сбросить» очищает весь список. Отдельного сброса отказов нет.

**2. Отпечаток вопроса** = модель + шаблон вопроса + текст промпта. Краткий/расширенный вид выдачи и текст карточки в отпечаток не входят: у вакансии один вердикт на вопрос, независимо от поиска, в котором она встретилась.

**3. Срок жизни отказов — две недели.** При поддержке хранилища удаляются отказы старше двух недель или с чужим отпечатком. К этому времени вакансия закрыта, а повторный запрос стоит доли копейки. Записи других причин не трогаются. Размер списка так ограничен сверху, отдельного бюджета не нужно.

**4. Одна вакансия — один запрос, последовательно.** Ни прохода по странице, ни пула, ни прогресса, ни пакетной записи, ни перечитывания страницы после ожидания. Карточка, по которой идёт запрос, остаётся в руках у скрипта; задержка 0,5 с теряется на фоне пауз 3–7 с между действиями.
- Платим только за карточку, до которой бот дошёл, а не за все 50 на странице.
- Повторы запроса не нужны: неудавшаяся вакансия пропускается, следующая карточка сама служит повтором.

**5. Запрос выполняет фон, запись делает скрипт списка.**
- Ключ и сеть живут в фоне (страница не может ходить на openrouter из-за CORS); образец — решение капчи сообщением.
- Фон принимает запрос только от вкладки работающего прогона: платим только за прогон.
- Ключ и промпт фон берёт из настроек сам, страница присылает только данные карточки.
- Фон без состояния: отвечает «вероятность и цена» либо видом ошибки. Единственный писатель чёрного списка в прогоне — скрипт списка (как и сегодня), гонок записи нет.
- Ответ записывается всегда, даже если Стоп нажат во время запроса: он оплачен.

**6. Не удалось оценить → вакансия пропускается на странице до её конца**, в список не пишется (новый прогон попробует снова). Не откликаться вслепую: фильтр не должен сам себя обходить.

**7. Сервис недоступен → прогон останавливается ошибкой.** Недоступен: нет ключа или промпта, отказ по ключу, балансу или модели (400, 401, 402, 403, 404), пять неудач подряд. Счёт подряд идущих неудач живёт в памяти скрипта: отклик возможен только после успешной оценки, так что перезагрузка страницы после отклика счёт и без того обнуляет.
- Вакансия без названия — не неудача сервиса: запрос не отправляется, пропуск, счёт не растёт.

**8. Результат отбора не пишется в журнал откликов, но виден в ленте.** Сорок пропусков на странице исказили бы историю откликов и дневной счёт, поэтому журнал откликов остаётся только для откликов и пропусков по словам человека. След отбора — запись-трассировка на каждый запрос в журнал диагностики (уходит на сервер по плану 05); лента «Последние события» рисует из неё по строке на каждый запрос: «✅ Отбор по Jev: компания — должность: 82% — пройдено» или «❌ … 31% — отклонено», со ссылкой на вакансию. Так сразу видно, что отбор работает. Отказ, известный из чёрного списка, повторной строки не даёт: запроса не было.

**9. Расход — одним накопительным счётчиком** (запросов и сумма), отдельным ключом. Отказов в списке для этого мало: одобренные тоже стоят денег. Счётчик растёт в скрипте в момент ответа.

**10. Единственный источник промпта и порога — настройки расширения.** Бенчмарк стартует с них; сделать свои значения рабочими он может только явной кнопкой (ползунок бенчмарка рабочий порог не двигает).

**11. Режим выключен по умолчанию.** Выключенный режим не читает отказы и не обращается к сети. Модель не настраивается (закреплённая версия); замена — через тот же контракт «карточка + вопрос → вероятность».

**12. Деньги — в рублях.** Сумма в долларах × 100, курс — одна константа. Формат «12 рублей 40 копеек» со склонением; меньше рубля — «40 копеек»; меньше копейки — десятые доли («0,2 копейки»). Хранимые данные остаются в долларах, пересчёт только при показе.
- Показываем: бенчмарк (плитки, цена запроса, строка стоимости в экспорте), аналитика (блок «Отбор»), проверка капчи в настройках, текстовая сводка отчёта диагностики.
- Не показываем: карточка запуска и лента — в ходе работы деньги не нагружают (цена запроса есть только в трассировке).

## Архитектура

### Опора в текущем коде
- Выбор карточки вызывается перед каждым откликом, каждый раз читает настройки: включение, выключение и смена порога подхватываются сами.
- Список «обработанных на странице» живёт в состоянии прогона и переживает перезагрузку после анкеты: оценённая и откликнутая вакансия не оценивается снова.
- Чёрный список уже хранит причину в записи; чтение целиком за миллисекунды.
- Фон уже принимает тяжёлые вызовы сообщениями и проверяет вкладку прогона (капча).
- Остановка зеркалится из хранилища, все ожидания через общую «дверь» прерываются мгновенно и стоят под паузой капчи.
- Подготовка к фиче — пять небольших шагов (ниже); без них пятое правило и новое сообщение стали бы костылями.

### Настройки
- Три поля: режим, промпт, порог (доля 0–1, в интерфейсе — проценты).
- Промпт по умолчанию — общая константа (сейчас лежит в бенчмарке и переезжает); порог по умолчанию 50%.
- Галочка недоступна без ключа OpenRouter (как у галочки LLM). «Старт» заблокирован с причиной, если режим включён, а ключа или промпта нет.

### Правила выбора карточки
- Бесплатные правила (обработана, чёрный список не-отбора, компания, стоп-слово) — чистый модуль: карточка + настройки + список → причина пропуска или ничего. Побочные эффекты (журнал откликов, обработанные) остаются за скриптом.
- Шаг отбора — второй небольшой модуль: карточка, список, настройки и функция запроса на входе → «отклик / пропуск / не оценена / недоступно» плюс запись для списка. Запрос подставной в тестах; сети и хранилища модуль не знает.
- Скрипт списка склеивает: бесплатные правила → шаг отбора → запись и счётчик → решение. Перед каждым запросом — проверка Стоп и паузы через общую дверь ожидания.

### Один читатель карточки
Сейчас два: у списка (идентификатор по кнопке отклика, поля только название и компания) и у бенчмарка (идентификатор по ссылке на вакансию, все поля). Для запроса списку нужны все поля. Читатель один; кнопка отклика — его дополнительное поле, карточки без кнопки список по-прежнему не берёт.
- Идентификатор один — по ссылке на вакансию (есть у любой карточки). Совпадение с идентификатором кнопки отклика проверяется тестом на сохранённых выдачах: от него зависит совместимость уже накопленного списка.

### Запрос и ошибки
Фон возвращает один из видов: оценено, нечего оценивать (нет названия), временная ошибка, недоступно.

| Что случилось | Что делает скрипт |
|---|---|
| Ошибка сети, 429, сбой провайдера, нечитаемый ответ, фон перезапущен посреди запроса | Вакансия пропущена на странице, счёт неудач +1; пятая подряд — ошибка прогона «сервис отбора не отвечает» |
| Нет ключа или промпта, отказ по ключу, балансу, модели | Сразу ошибка прогона с текстом, что сделать (проверьте ключ и баланс OpenRouter или выключите отбор) |
| Нет названия | Пропуск, запроса нет |
| Стоп посреди запроса | Ответ записывается, дальше тихий выход |

### Диагностика
- Трассировка на каждый запрос: вакансия (название и компания), вероятность, решение, цена, время; для неудачи — вид ошибки. Из неё же рисуется лента и считается сводка отчёта.
- Снимок состояния для отправки на сервер получает режим, порог и отпечаток промпта (текст не уходит, как у остальных промптов).
- Отчёт диагностики получает строку-сводку: запросов, отказов, неудач, цена, причина остановки.

## Интерфейс
Вставки в существующие места, новых экранов нет.

**Настройки — блок «Отбор вакансий по Jev»:** галочка; промпт; порог в процентах; кнопка бенчмарка (переезжает из «Диагностики и отладки»); число отказов отбора рядом с существующим «Сбросить» (рядом же число прочих записей); пояснение, что текст вакансий и промпт уходят в OpenRouter и дальше модели, и что отбор точнее в расширенном виде выдачи (со сниппетами).

**Карточка запуска:**
- До старта в подсказке под «Старт»: «Отбор по Jev включён, порог 50%». Выключен — строки нет.
- Во время прогона: «Отбор: отклонено N». Число — записи отказов со временем не раньше старта прогона; отдельных счётчиков в состоянии прогона нет, перезагрузка после анкеты ничего не удваивает.
- Остановка «вакансии закончились» при включённом режиме добавляет «из них отклонено отбором: N».
- Ошибка сервиса — красным текстом статуса.

**Лента «Последние события»:** по строке на каждый запрос к модели — иконка ✅ (пройдено) или ❌ (отклонено), компания, должность, вероятность в процентах и итог, ссылка на вакансию. Строки не попадают в историю откликов и дневной счёт. Лента показывает последние 36 событий, на странице из пятидесяти вакансий строки отбора могут вытеснить из неё отклики.

**Аналитика — блок «Отбор»:** оценено, отклонено при текущем пороге, потрачено; таблица последних отклонённых (название, компания, вероятность, ссылка на вакансию). Назначение — проверить, не отсеивается ли нужное, и подобрать порог.

**Бенчмарк:** открывается с рабочими промптом и порогом, пока нет своих; «Сделать рабочими» (промпт A и порог → настройки; отказы по старому вопросу перестанут действовать); «Взять рабочие». Пул и повторы остаются внутри бенчмарка.

**Не делаем:** строка в ленте на вакансию, известную из чёрного списка (запроса не было); пометки на карточках hh.ru (план 03: видимые элементы расширения в странице); ручной вердикт; режим «оценивать, но не пропускать» (для этого бенчмарк); оценку по полному тексту вакансии (запрещено планом 03); заранее проход по всей странице.

## Поведение по сценариям

| Ситуация | Поведение |
|---|---|
| Режим выключен | Как сегодня: отказы не читаются, сеть не трогается |
| Включить без ключа или промпта | Галочка недоступна без ключа; «Старт» заблокирован с причиной |
| Включили посреди прогона | Следующая карточка уже идёт через отбор |
| Выключили посреди прогона | Следующая карточка без отбора; ранее отклонённые доступны для отклика сразу |
| Сменили порог | Со следующей карточки, запросов нет (вниз и вверх) |
| Сменили промпт / обновилось расширение с новым вопросом или моделью | Старые отказы не действуют, вакансии спрашиваются заново; устаревшие записи удалит поддержка хранилища |
| Та же вакансия на другой странице, в другом поиске, в новом прогоне | Известный отказ: запроса нет |
| Отказ, потом порог опустили ниже вероятности | Вакансия снова кандидат на отклик без запроса |
| Отказ действует, анкеты нет | Пропуск без записи в журнал откликов |
| Одобрена, анкету заполнить не удалось | Запись «анкетной» причины, как сегодня |
| Одобрена, Стоп до клика | При новом старте вопрос задаётся снова (доля копейки) |
| После анкеты список перезагрузился | Обработанные на странице пропускаются без запросов |
| Всё на странице отклонено | Конец страницы → следующая; темп листания — на проверку при приёмке |
| Больше страниц нет | Остановка «вакансии закончились» с числом отклонённых отбором |
| Карточка без названия | Запроса нет, пропуск |
| Одна вакансия не оценилась | Пропуск до конца страницы, запись в трассировку |
| Сервис лежит | Пять неудач подряд → ошибка прогона |
| Дневной лимит | Остановка до любого запроса |
| Капча / Стоп | Перед запросом общая дверь ожидания: под капчей бот стоит, Стоп прерывает сразу |
| Закрыли вкладку или браузер | В списке всё записанное; потерян максимум один запрос в полёте |
| Ответ Jev поменял форму (альфа) | Как временная ошибка → остановка по пяти подряд; в трассировке — что пришло |
| Экспорт / импорт | Список и счётчик едут в общем файле; записи проходят проверку; старый ключ списка переносится после импорта |
| Режим ассистента | Не влияет |

## Подготовка (рефакторинг без изменения поведения)
- **Одна функция денег.** Сейчас доллары форматируются в двух местах бенчмарка (интерфейс и экспорт), в проверке капчи и в сводке диагностики. Один модуль: курс, пересчёт, склонение, доли копейки; тесты бенчмарка с долларовыми строками обновляются.
- **Один читатель карточки** (см. выше).
- **Бесплатные правила — чистый модуль**; тесты фиксируют прежнее поведение четырёх правил.
- **Чёрный список вакансий:** общее имя и причины, перенос ключа, чистка по сроку и отпечатку; места чтения и записи (скрипты списка и анкеты, настройки) переведены.
- **Обёртка сообщений фона:** четыре одинаковых блока «вызвать, ответить, при ошибке записать и ответить ошибкой» сводятся к одной обёртке; новое сообщение — одна строка.

Согласование с планом 03: рефакторинг 0.1 (готов, ручная проверка не закрыта) меняет тот же скрипт списка — проверить до начала; запросы отбора не «пауза» и в модуле темпа не учитываются.

## Этапы
- **Этап 0 — формулировка и порог (хвосты плана 04).** Проверить формулировку на другой выдаче, выбрать порог (зона 40–50% серая). Результат — рабочие промпт и порог по умолчанию. Блокирует приёмку, не реализацию.
- **Этап 1 — подготовка** (список выше), каждый шаг отдельно.
- **Этап 2 — ядро.** Отпечаток; шаг отбора; правило действия записи (отпечаток, порог, режим); срок жизни; счётчик расхода. Всё с тестами и подставным запросом.
- **Этап 3 — подключение.** Сообщение фона и проверка вкладки прогона; вызов шага из скрипта списка; запись, счётчик, трассировка; ошибка прогона.
- **Этап 4 — интерфейс.** Блок настроек, блокировка «Старт», карточка запуска, аналитика, бенчмарк ↔ настройки.
- **Этап 5 — сопутствующее.** Снимок состояния и сводка диагностики, документация, обновление плана 04.
- **Этап 6 — приёмка и релиз.** Версия по порядку выхода (после 1.6.1).

## Риски
- **Jev — альфа.** Форма ответа может смениться. Закреплённая версия, нечитаемый ответ — временная ошибка, замена модели — за тем же контрактом.
- **Серая зона 40–50%.** Вакансии без признаков отрасли (только название) при пороге 50% отсеиваются. Порог — единственный рычаг и двигается без запросов; отдельное поведение «серой зоны» — открытая идея плана 04.
- **Краткий вид выдачи.** Оценка по краткой карточке менее информативна, а отпечаток вид не учитывает: отказ, полученный в кратком виде, действует до двух недель или до смены вопроса. Смягчение — подсказка про расширенный вид; сброс — кнопка «Сбросить».
- **Листание при массовых отказах.** Если выдача в основном отклоняется, бот быстро листает страницы почти без откликов. Паузы между страницами есть (3–7 с); смотреть при приёмке.
- **Размер списка и запись целиком.** Каждая запись — чтение и перезапись массива. Две недели срока удерживают размер в пределах мегабайта; проверить время выбора карточки на большом списке при приёмке.
- **Приватность.** Текст вакансий и промпт уходят в OpenRouter и дальше; указано в настройках.
- **Цена.** Ожидание около 0,2 копейки за вакансию; подтвердить вживую.
- **Ступенчатая отрисовка hh.** Недорисованный сниппет даёт оценку по менее полной карточке; проверить вживую, сколько сниппетов в DOM на момент выбора.

## Ручная приёмка
- Выключено: прогон как раньше, запросов к Jev нет, в панели про отбор ничего нет.
- Включено: до старта видна строка про отбор; в прогоне «отклонено N» сходится с таблицей в аналитике.
- Свежая страница на 50: вакансии оцениваются по одной, отклонённые пропускаются, одобренные получают отклик; прирост «потрачено» совпадает с расходом OpenRouter × 100.
- Стоп и Старт, закрытая вкладка и Старт: оценённое не запрашивается заново.
- Повтор прогона на той же странице: ноль запросов.
- Анкета → возврат на список: запросов нет.
- Сменить порог в ходе прогона: следующая карточка по новому порогу, запросов нет.
- Сменить промпт: вакансии спрашиваются заново.
- Выключить в ходе прогона: бот начинает откликаться на ранее отклонённых.
- Неверный ключ или нет баланса: ошибка прогона с понятным текстом. Отключённая сеть: остановка после пяти неудач подряд.
- Экспорт → импорт, в том числе файл со старым ключом списка.
- Краткий вид: подсказка в настройках.
